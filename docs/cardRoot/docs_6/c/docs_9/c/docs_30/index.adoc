User programs can define _calculated fields_. A calculated field is declared in the card type definition (`"isCalculated": true`) and gets its value from a logic program rule with a `{{#xref}}"cardKey":"docs_ob1wsa0g"{{/xref}}` head.

This is best explained with an example. Assume that a card type risk has two integer fields `likelihood` and `impact`, which range between 1..3. The following logic program adds a calculated field `riskLevel`, ranging between 1..9, calculated with the formula `likelihood * impact`, to all cards of the card type risk that have the fields `likelihood` and `impact`.

[source]
----
fieldCalculated(X, "moduleName/fieldTypes/riskLevel", Likelihood * Impact) :-
    field(X, "cardType", "moduleName/cardTypes/risk"),
    field(X, "moduleName/fieldTypes/likelihood", Likelihood),
    field(X, "moduleName/fieldTypes/impact", Impact).
----

Cyberismo derives the effective `{{#xref}}"cardKey":"docs_8mg8p068"{{/xref}}` value from `fieldCalculated` automatically.

Defining a calculated field with a plain `field` head is deprecated. It still works when the field does not enable override, but it cannot support overrides: when an override exists, the field ends up with two conflicting values, and Cyberismo shows a "Conflicting field values" notification on the affected cards. For an override-enabled list field, a plain `field` head silently merges the override and calculated values instead.

== Overriding calculated values

A calculated field can allow user overrides by setting *Enable override* on the field in the card type definition (`"enableOverride": true`). Users can then enter a value for the field; the value is stored in the card and Cyberismo generates a `{{#xref}}"cardKey":"docs_6h0t096b"{{/xref}}` fact for it. The override becomes the effective `field` value, which is what the user interface shows for the field, marked as overridden. When the field is being edited, the user interface shows the calculated value next to the override being edited.

An override can also be set on a template card. A template card has no calculated value of its own, so the field is presented as an override with no calculated value. Every card created from the template starts with that override in place: the card shows the override rather than its own calculated value until someone clears it.

Clearing an override removes the stored value from the card, and the calculated value applies again. Clearing stays available even for a field that no longer allows override, so that a value stored while override was enabled can still be removed after it has been disabled.
