The `field` macro shows a field of a card, and lets users with the right role edit it in place. It works for custom fields, and for the built-in `title` and `workflowState`.

== Parameters

The `field` macro supports the following parameters:

* `"field"`: The field to show (required). Use the full name of a custom field, such as `base/fieldTypes/owner`, or one of the built-in names `title` and `workflowState`. A bare name such as `owner` is an error.
* `"showLabel"`: Whether to show the field's label before the value (optional, default `true`).

The macro always shows the field of the card that contains it. In a card that another card includes with the {{#xref}}"cardKey":"docs_61tj2hec"{{/xref}} macro, that is the included card, not the card that includes it.

The field must belong to the card's card type. If it does not, or the field does not exist, the macro shows an error.

== Example

Consider the following AsciiDoc snippet:

```
{{#raw}}

{{#field}}
    "field": "base/fieldTypes/owner"
{{/field}}

{{#field}}
    "field": "workflowState",
    "showLabel": false
{{/field}}

{{/raw}}
```

The first macro shows the owner field with its label. The second shows only the workflow state of the card.

== Visibility

A field's visibility in the card type (_always visible_, _optionally visible_ or _hidden_) decides whether the field appears in the metadata panel of the card. It does not limit the `field` macro. A hidden field can still be placed with the macro, and its value then appears in the application, in the static site and in exports. Placing a hidden field in the content is the author's choice.

== Editing

In the application, the macro shows the field as an editor, with its own save and cancel buttons. The macro is read-only when:

* the user's role is below Editor;
* the field is calculated, unless the card type allows overriding it (see {{#xref}}"cardKey":"docs_27"{{/xref}});
* the user may not edit the field, as decided by an `editingFieldDenied` rule (see {{#xref}}"cardKey":"docs_eqgqllcc"{{/xref}});
* the card is shown as a template card preview.

For `workflowState`, the macro shows the transitions that are available from the current state. Transitions that are denied are shown disabled one by one, with the message that explains why. Only the user's role and the template card preview make the state selector read-only; the other rules above do not apply to it.

== Static site and export output

In the static site and in exports (such as PDF and AsciiDoc), the macro shows the value as plain text. The text is not interpreted as AsciiDoc, so a value cannot add formatting or other macros. The label, if shown, is in bold. The label is the field's display name; for the built-in `title` and `workflowState` it is `Title` and `Workflow state`.

[cols="1,3"]
|===
| Data type | Output

| Enumeration | The display value of the selected option, or the stored value if the option has no display value
| List | The values joined with a comma and a space
| Boolean | `Yes` or `No`
| Date | The date as it is stored
| Date and time | `YYYY-MM-DD HH:mm UTC`
| Person | The email address as it is stored
| Text and number types | The value as it is stored
| Calculated field | The effective value, formatted by the data type
| Multi-line text | The text, with line breaks kept
| Empty value | `—`
|===

== Where to place the macro

In the application the macro is a block, so in running text the value appears on its own line there. Static site and export output renders it inline. You can use it in inline text, in paragraphs, or in a table cell that starts with `a|`.

Do not use the macro:

* in block attribute lists, such as `[#id]`, `[.role]` or `[title=...]`;
* as the target of a `link:` or `image:` macro;
* in a table that uses a custom `separator`, or the `format=csv` or `format=dsv` options.

In these places the value is not protected, and it can corrupt the output.
