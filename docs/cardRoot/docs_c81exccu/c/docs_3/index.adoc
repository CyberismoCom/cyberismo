The best way to learn how to use the Cyberismo command-line interface is the built-in help. To see the top-level help, execute the following command:

[source,console]
----
$ cyberismo help
----

The help command prints an overview of the available commands:

[source,console]
----

CLI tool to handle tasks.

  -v, --version                                                            Output the version information

  -h, --help                                                               Display help for command

Commands:
  add [options]                                                            Add items to the project
  calc [options]                                                           Used for running logic programs

Many commands have subcommands. For example, `create` has subcommands for each resource type:

[source,console]
----
$ cyberismo create help

Usage: cyberismo create [options] [command]

Create cards, resources and other project items

Commands:
  attachment <cardKey> <filename>                   Create an attachment for a card
  card <template> [parentCardKey]                   Create a card from a template
  cardType <name> <workflow>                        Create a new card type
  fieldType <name> <dataType>                       Create a new field type
  graphModel <name>                                 Create a new graph model
  graphView <name>                                  Create a new graph view
  calculation <name>                                Create a new calculation
  label <cardKey> <labelName>                       Create a label on a card
  link <source> <destination> <linkType> [desc]     Create a link between two cards
  linkType <name>                                   Create a new link type
  project <name> <prefix> <path> [cat] [desc]       Create a new project
  report <name>                                     Create a new report
  skill <name>                                      Create a new skill
  template <name> [content]                         Create a new template
  workflow <name> [content]                         Create a new workflow
  resource <resourceName> [content]                 Create a new resource
  help [command]                                    display help for command
----

To get detailed help for any command, add `help` after the command name:

[source,console]
----
$ cyberismo show help
----

== Removing dormant field values

The cards of a project may contain custom field values that nothing reads, for example the values of a field that has been removed from the card type. Such values are dormant: they stay in the card files, but they are not shown in the user interface and they are not visible to logic programs, as described in {{#xref}}"cardKey":"docs_27"{{/xref}}. To remove them, enter the following command in the Cyberismo project directory:

[source,console]
----
$ cyberismo clean
----

The command lists every value that it removes and the reason for removing it: `undeclared` for a field that the card type does not define, `calculated-locked` for a value of a calculated field that does not allow overrides, and `null-value` for a custom field whose stored value is empty (null or an empty string).

The command updates the cards of the project and the cards of the templates that the project itself defines. Cards that come from imported modules are read-only and are never changed.

To see what the command would remove without changing any card, add the `--dry-run` option:

[source,console]
----
$ cyberismo clean --dry-run
----

== Logs

Commands that work on a project write a log of what they did to the `.logs` folder of the project. Each day has its own file, named `cyberismo-YYYY-MM-DD.log` after the date when the command started, for example `.logs/cyberismo-2026-11-10.log`. Each line of the file is a JSON record, and the file contains messages of all levels. The `.logs` folder ignores itself in git, so the logs never show up as changes in the repository.

The `cyberismo app` command writes to the same place. If it serves a folder of several projects, the log file is in the `.logs` folder of that folder.

Logs are not printed on the terminal by default. To also see them, use the `-L` option with the lowest level that you want to see. The levels are `trace`, `debug`, `info`, `warn`, `error` and `fatal`, and the logs are written to the standard error stream (stderr) so that the results of the command on the standard output stay the same:

[source,console]
----
$ cyberismo -L debug validate
----

Commands that do not use a project, such as `cyberismo preview`, do not write a log file, but they accept the `-L` option. If the project folder is not writable, no log file is written, and the command runs normally.

When you need to send the logs to support, zip the project folder. The archive includes the `.logs` folder.
