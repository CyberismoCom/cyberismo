The ideas behind Cyberismo. Read this section when you want to understand *why* the tool is shaped the way it is, rather than how to perform a particular task.

Cyberismo is built on three ideas that reinforce each other.

Everything is a card, and every card is a file:: A card is the unit of information: a risk, a control, a security requirement, a threat, an architecture decision, a review task, a controlled document. Technically it is a directory holding an AsciiDoc document, a JSON metadata file and any attachments. Cards have types, types have workflows, and cards link to each other with typed links. The result is not a pile of documents but a graph.

The graph can be reasoned about:: Because the content is a typed, linked graph rather than free text, a logic program can evaluate it. Cyberismo embeds Clingo, an Answer Set Programming solver, and uses it to compute progress metrics, calculated fields, reports, notifications and automated policy checks, explaining each verdict in a sentence.

The practice itself is content:: Card types, workflows, templates, link types and logic programs are packaged into reusable modules. A team imports a module and has a working process immediately, then adapts it until it becomes theirs. Cybersecurity practice can be shared this way instead of being reinvented by each organisation.
