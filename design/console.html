01 — Foundations

Two rules hold the system together

Both are stated in the header comment of theme.ts, and both are machine-enforced. Everything else follows from them.

Rule one

One corner

Radius is 2px everywhere — buttons, inputs, cards, chips, menus, dialogs. 0 for full-bleed bars and status rails, 9999px for avatars only. The marketing site ships radius 0 on every CTA; 2px is that geometry made workable for form controls.

Rule two

No blue

Primary action is ink, inverting on dark. Amber carries in progress. The brand orange is reserved for the focus ring and the logo. Semantic colour is the only colour in the app that means anything.

Why ink and not orange. #FF530F at UI text sizes on white is 3.1:1 and fails AA — and in a product with genuine failure states, an orange button reads as an alarm. The amber-on-ink pairing is the marketing site's own CTA treatment, and in the app it marks the single primary control in the app bar.

03 — The central device

Workflow state

Every card sits in exactly one workflow category, and that is the app's most important signal. It is carried by a square mark at the start of the row in a list, or a 3px rail on the leading edge of a panel. Both encode the same four states.

The rail came first and was wrong for lists. A 3px line sits at a spatial frequency where the eye's colour channels are least sensitive, so the marks blurred together — measured, "not started" and "done" were only 1.31:1 apart, and with hue removed "done" and "failed" were 1.14:1: the same mark. Retuning the hues cannot fix that, because a mark on white needs 3:1 to read at all, which caps three states to roughly 1.9:1 from each neighbour. The same colour in a compact dot sits where chromatic sensitivity is highest — and the dot is the shape the app already used for workflow state, so the tree and the state selector read as one idea rather than two.

State Light Dark Meaning
initial #73787F #6B7280 Draft, not started
active #C26A00 #FFB93D In progress — this is the brand gold, doing real work
closed #1B7F4B #4BC77F Approved, done
error #A81E12 #F0705A A failed policy check. Not a workflow category — it arrives as a tree node's statusIndicator

How it resolves

The four states are CSS variables declared on :root and re-declared under [data-joy-color-scheme='dark'] in globals.css, so they follow the colour scheme without a React re-render. Components never name a state colour directly; they call one of two resolvers in lib/utils.ts.

Resolver Contract
getStateColor(category) Maps a workflow category (or 'error') to var(--cy-state-*). Unknown input returns transparent rather than guessing.
getProgressColor(value) ≤0 → initial, ≥100 → closed, otherwise active. Exists because project and phase cards report progress but carry no workflow state of their own — without it their rail would be transparent.

label is a custom level, and it exists because of a bug. The uppercase tracked treatment was first applied to Joy's shared body-xs — which is used across the app for values, counts and hints, not only labels. Every metadata value started shouting ("AUG 17, 2026", "PRODUCT.OWNER@EXAMPLE.COM"). The treatment now lives in its own level, declared to TypeScript in src/joy.d.ts. Never style a shared typography level.
An eyebrow is not a row label. The second half of that mistake took longer to see: the label level was also applied to metadata field labels, where it fails three ways. Uppercase with 0.09em tracking is about 38% wider — "Information classification" goes from 144px to 199px and wraps a 168px column. At weight 800 the label out-weighs its own value (700), so the label shouts and the content whispers. And uppercase destroys the word shape that makes a repeated column scannable. Measured across the 99 field labels in the demo projects, the eyebrow treatment fits 61 on one line where sentence case fits 86. Use label for section eyebrows — few, short, isolated — and sentence case at text.tertiary for anything that labels a row.

Weights

Three ship: 500 body, 700 headings and controls, 800 page titles and every uppercase label. No 400 — it goes thin against warm neutrals — and no 600, which is where undisciplined hierarchies hide.

05 — Foundations

Geometry

Radius
2px

xs: 0 for bars and rails; sm/md/lg/xl: 2px. Twelve Joy components pin it again in styleOverrides, so a component that ignores the theme scale still lands on 2px.

Borders
1px

Structure is drawn with hairlines, never shadows. divider groups; outlinedBorder marks anything you can type into.

Elevation
One

shadow.xs and sm are none; md, lg and xl are the same overlay shadow. If it doesn't float above the page, it doesn't lift.

Focus

A single treatment everywhere: 2px solid accent, 2px offset. Set both in the Joy theme's focus.default and as a bare :focus-visible rule in globals.css, so it also covers plain DOM elements and rendered AsciiDoc content. This is the only place the brand orange appears outside the logo.

06 — Foundations

Density

theme.ts exports a DENSITY object for layout constants. Three of its six tokens are wired up; the other three are declared but unused, and two of those disagree with what the app actually does.

Token Declared Status Reality
appBarHeight 48 Wired AppToolbar height and the Main height calculation
figureColumn 38 Wired ProgressMeter's reserved figure column
railMinWidth 220 Wired TwoColumnLayout's leftPanelMinSize default
rowHeight 32 Unused Tree rows are actually 28px, set on react-arborist in BaseTreeComponent
railWidth 280 Unused The panel default is 20%, not a pixel value
documentMeasure 72ch Unused No component reads it
A token that lies is worse than no token. rowHeight: 32 and railWidth: 280 read as authoritative but describe nothing — anyone trusting them would be wrong by 4px and by a whole unit system. Either wire them up or delete them; see Known gaps.

The metadata label column

168px, capped from a 40% width. Field labels run to 54 characters in the demo projects ("Does the interface or dataflow cross a trust boundary?"), so wrapping cannot be designed away — it has to be graceful. 168px is where the curve flattens: of 99 real labels it fits 86 on one line against 71 at 150px, and the info icon sits inside the label box, costing about 18px of it. Rows align on their first line, so a two-line label beside a one-line value still reads as one row.

The metadata rail and the lock lane

Every metadata row carries a persistent 2px rail on its leading edge, in --cy-rail, drawn as a ::before on the row rather than a border, and a 27px lane to the left of the text. This is the one place a rail earns its keep. Elsewhere a thin line is the wrong carrier for meaning (see the state marks) — here it carries no meaning at all. It is a bracket: two- and three-line labels beside multi-line values have no other cue for where one row stops, because the 8px row gap is smaller than the 17px line leading inside a wrapped label. Without the rail a wrapped label groups with the wrong value by simple proximity. It is always painted, never on hover: readability that appears only under the pointer is not readability.

The rail has its own token because the scale has no step where it needs one. divider put it at 1.25:1 against the page — a line nobody could see, doing none of the bracketing it exists for — while neutral.400 is 2.36:1 and neutral.500 4.63:1, close enough to the label's own 6.47:1 to compete with it. --cy-rail is tuned to 3:1, the non-text threshold, in both schemes: a 2px mark is high spatial frequency and needs more contrast than a filled area to read as present at all.

Three steps that stay in order: --cy-rail at rest, --cy-rail-strong on hover for a clickable row (the rail is also the row's affordance, so no separate hover border is needed), and --cy-editing at full ink while the row is being edited.

The padlock on a read-only field is outdented into the 27px lane, left of the rail, at left: 0. Inside the label it used to shift the first line of text by its own width, so locked and unlocked labels started at different x-positions and the column lost its vertical rhythm: measured, 321px against 339px. Outdented, all 25 labels on a card share one left edge. The rail sits at 17px, inside the lane rather than at its end: the padlock's ink is only 9.3px of its 14px box, so a rail at the lane's end had 11px of slack on the lock's side and none on the label's — the label began exactly at the rail. Split the other way, the label gets the 8px gutter it needs and the lock keeps the 5px it can spare, with the label column staying where it was, 2px from the document text below. It is centred on the first line's cap height, not on the row box — top: calc(0.75rem * 1.45 / 2 - 7px) — which holds regardless of how many lines the label wraps to.

The lock must live outside the accordion. MuiAccordionDetails sets overflow: hidden on both its root and its content, so a lock positioned into the lane from inside it is silently clipped — it measures correctly and paints nothing. It is a sibling of AccordionDetails, inside the Accordion, which owns both the lane padding and the rail. The corollary: living outside the details element means neither the lock nor the rail collapses with it, so both are withheld on a collapsed row — otherwise every hidden read-only field stacks another padlock on the same pixel, beside the "Show more" button.

The navigation figure column

Rows carrying a progress metric reserve a fixed 38px right-aligned column in tabular figures. The percentage is always shown in full, including 0% and 100% — never rounded to a bucket, never abbreviated, never hidden behind a hover. Under width pressure the label truncates and the bar collapses to a 20px minimum; the figure is the last thing standing. Rows with no metric reserve nothing.

This costs less than it appears: across both demo projects (164 nodes, six levels deep) every progress-bearing row has a title of 6–17 characters, because progress belongs to projects and phases. The long titles live deeper in the tree, where no row carries a percentage at all.

07 — A standing exception

The app bar does not follow the palette

It keeps its ink ground in both colour schemes — --cy-chrome, which is #2A2A2A in light and goes further down to #0C0D10 in dark so the bar still separates from the page.

App bar48px · ink in both schemes
CYBERISMO/☀+ Create cardSL
The consequence, learned the hard way. Anything sitting on the bar cannot take its colour from the palette. In light mode neutral plain resolves to #3D4149, roughly 1.4:1 against the bar — the mobile menu button was effectively invisible. On-chrome controls are painted white explicitly, via the shared APP_BAR_ICON_SX constant in AppToolbar.tsx. If you add a control to the app bar, use it.
08 — Kit

Components

The system adds only two components. Everything else is a Joy component with theme-level defaults — the point of the token layer is that the existing app renders this way without per-component work.

The tree row, as built

CardTreeNode composes the whole system in one row: rail, optional error mark, truncating title with a native title tooltip, and the figure column. Its rail colour resolves in three steps — workflow state if there is one, else the progress colour, else transparent — which is what keeps project and phase rows from going blank.

Document content

Rendered AsciiDoc is styled in globals.css against the same tokens. Links are ink with a gold underline, hovering to the accent — the treatment the brand already specifies, and the reason there is no blue left anywhere in the product. Code and <pre> take the vendored mono face; headings take the display weight.

09 — Enforcement

What the linter will not let you do

Both rules drifted badly before the system existed — 270 inline sx blocks across 84 of 156 files, and seven different corner radii. They are enforced rather than documented. designSystemGuard in eslint.config.mjs covers src/components/** and src/pages/**.

Rejects Message
Raw hex colours
#abc / #aabbcc 		Use a palette token (e.g. "text.secondary") or a --cy-* variable; brand values live in theme.ts.
Off-system radii

10 — Language

Words are part of the system

The design system's voice rule is direct, dry, British English, no emoji, no exclamation points — the logo owns the brand's only "!". Verified across all 480 strings in locales/en/translation.json.

Casing
Sentence

Labels, buttons, headings and menu items. No Title Case except proper nouns.

Shouting
None

FAIL/PASS became Failed/Passed — the rail carries the emphasis now.

Buttons
Outcome

"Create card", not "Create" — the control says what will happen.

One noun per concept

Concept Always Never
A unit of recorded work Card item, document, page, entry
Anything configurable Resource asset, object, definition
An imported bundle Module package, plugin, extension
A card's schema Card type type, class, kind
An automated rule result Policy check validation, control, rule, test

"Cards" stays the domain noun — it is load-bearing across the CLI, the MCP tool names, card types and the docs. What changed is that it is no longer used as a destination: the configuration back-link now reads "Back to project", which names something real and stays true whichever card you came from.

11 — Honest edges

Known gaps

Where the system is not yet true, so nobody has to rediscover it.

  • Three DENSITY tokens are unused, and rowHeight (32) and railWidth (280) contradict the real values (28px and 20%). Wire them up or delete them.
  • Disabled and placeholder text sits below AA — around 2.2:1 in light and 3.2:1 in dark on the workflow editor. WCAG 1.4.3 exempts inactive controls, so this is defensible, but it is the weakest surface in the product and it predates the refresh.
  • CodeMirror carries its own themes (githubLight / vscodeDark in constants.ts). The frame now uses palette tokens and a 2px corner, but the editor interior is still styled by those imports rather than by this system.
  • Two typefaces, one brand file. The design system's colors_and_type.css still pulls IBM Plex Mono from Google Fonts by @import; only the app vendors it. Worth aligning before the marketing site ships anywhere restricted.
  • BRAND.cream is exported but unused. Cream was deliberately demoted from page ground to nothing in the app; the constant remains for the marketing side.
Where to change things. Brand values — accent, ink, gold, typefaces, spacing, radius — belong to the Cyberismo design system project and flow down. Density, workflow state and the dark palette are decided in theme.ts, because those need real screens and real data to get right. If a change touches both, start with the brand file.
